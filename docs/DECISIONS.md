# Architecture decision log

- **ADR-001 — Python-authored frontend:** NiceGUI could not be installed in the offline build container. Use Jinja2-rendered HTML/CSS through FastAPI without author-written JS. OBS uses 3-second HTML refresh. Reconsider a Python UI framework once a package-connected environment is available.
- **ADR-002 — SQLite first:** Single-process transactional DB is appropriate for a hackathon MVP; do not deploy multiple uncoordinated workers.
- **ADR-003 — Clean-room Poketar inspiration:** Preserve original ideas (customize/iterate/preview) but copy neither legacy code nor franchise assets.
- **ADR-004 — Strict story approval:** AI emits structured proposals. Only an authenticated host can approve canonical changes.
- **ADR-005 — EventSub first:** Twitch WebSocket user-token subscription is simpler for a quick live proof than Extension deployment and review.
- **ADR-006 — Deterministic offline generator:** Offline mode is explicitly labeled and allows judges to exercise the UI without AI credentials. It does not satisfy proof of real AI generation or live Twitch connectivity.
- **ADR-007 — Non-destructive branching:** Old story nodes persist, canon is the ancestor chain of the selected head, and forks mark previously chosen paths as alternatives.
- **ADR-008 — Persisted pause origin:** A paused story stores its prior effective stage. Resuming a paused vote returns to `VOTING`; it does not silently create a new `READY` state or accept votes while paused.
- **ADR-009 — Database voting invariant:** A partial unique SQLite index permits at most one `OPEN` voting round per story session. Service checks remain the user-facing error path, while the index protects concurrent writers.
- **ADR-010 — Bounded canonical context:** Generation receives at most six canonical ancestors and a 3,800-character synopsis, plus bounded approved contributions and persona descriptors. Alternate branches and private Twitch identifiers are excluded.
- **ADR-011 — Redacted diagnostics:** `python -m storyforge doctor` reports local shape checks for every supported environment variable without returning values. External OAuth/model checks require an explicit `--live` flag and run in time-bounded subprocesses; the report never treats local syntax as external verification.
- **ADR-012 — Confirmed EventSub trust:** Mark the connector live only after Twitch returns a matching enabled `channel.chat.message` WebSocket subscription. Reject notifications without the configured broadcaster ID or expected subscription type/version.
- **ADR-013 — Safe provider configuration and failure display:** AI base URLs must use HTTPS outside demo loopback, exclude embedded credentials/query/fragment, and omit the already-appended completion path. Reject provider responses explicitly marked truncated; expose only transient exception types in Twitch status.
- **ADR-014 — Chat write control:** All recognized commands share a short per-viewer in-process cooldown before another receipt is written. Unknown and informational commands create no durable receipts; recently cooldown-rejected event IDs are held in a bounded ten-minute in-process cache. Accepted receipts remain durable in SQLite. This is not a distributed rate limiter, and the in-memory cooldown/dropped-event cache resets on process restart.
- **ADR-015 — Environment-driven settings evaluated per instance:** Dataclass defaults read the environment when `Settings()` is constructed. Tests and command processes can therefore isolate/override configuration without import-time environment capture.
- **ADR-016 — Durable generation outcome:** Story sessions persist `AWAITING`, `FAILED`, validated `AI-GENERATED`, or `DEMO-GENERATED` status. Approval is represented by the canonical node and resolved proposal state, while the story retains the generation provenance. A failed model call remains visible after refresh/restart; only a validated provider response receives the AI-GENERATED label.
- **ADR-017 — Redact settings representations:** Secret-bearing Settings fields are excluded from the dataclass representation so a routine exception/test report cannot print configured credentials. Keep explicit sentinel tests for this boundary.
- **ADR-018 — Serialize model generation per app:** An app-instance async lock prevents concurrent host actions from issuing duplicate model requests or creating competing proposals. This matches the single-process MVP and does not coordinate separate workers.
- **ADR-019 — Keep Twitch OAuth on the configured origin:** The OAuth redirect URI remains derived from `APP_BASE_URL`. A pure ASGI middleware redirects every off-origin HTTP request to the fixed configured origin before session handling and preserves the requested path/query. Redirect targets never come from the incoming Host header. Callback failures return to the configured app home; state mismatch remains rejected before token exchange.
- **ADR-020 — Keep the crypto dependency patched:** `pip-audit` reported seven advisories for `cryptography` 47.0.0. Set the runtime floor to 50.0.2 and re-run the dependency audit when updating the install set.
- **ADR-021 — Avoid a blocking middleware bridge:** Canonical-origin redirects and security headers use pure ASGI middleware rather than Starlette `BaseHTTPMiddleware`. This keeps the security boundary simple and avoids adding another AnyIO task-group bridge around every request.
