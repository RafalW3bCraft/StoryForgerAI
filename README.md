# AI StoryForge — The Living Twitch Narrative

AI StoryForge is a Python-first storytelling tool for Twitch. The host directs a branching story and plays a character; viewers join with persistent fictional personas, customize original procedural SVG avatars, contribute moderated ideas, and vote on scene choices. SQLite preserves the canonical path and alternative branches. A browser-source page presents the current story for OBS.

This repository contains an initial MVP that predates the current Codex engineering pass. Codex changes and live verification are recorded separately in `docs/CODEX_BUILD_LOG.md` and `docs/RELEASE_REPORT.md`. Do not infer hackathon eligibility or external API success from a local demo.

## Architecture

- Python 3.12+ application: FastAPI, Jinja2 templates, CSS, SQLAlchemy and SQLite.
- Python-only Twitch OAuth and EventSub WebSocket integration; no application-authored JavaScript or TypeScript.
- Persistent identities use immutable Twitch user IDs. The viewer simulator is explicitly labeled synthetic and works only in demo mode.
- Scene proposals pass Pydantic validation and remain noncanonical until the authenticated host approves them.
- Live AI uses a configured OpenAI-compatible `POST {AI_BASE_URL}/chat/completions`; deterministic demo generation is explicitly labeled DEMO and is never an automatic fallback after live inference fails.
- `/overlay` refreshes every three seconds; `/graph.svg` is generated by Python.

## Install and run

From the checked-out repository, use Python 3.12 or newer:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env
```

Set a unique `STORYFORGE_SECRET` and a strong `DEMO_ADMIN_PASSWORD` for a local demo. Then run the redacted diagnostic and start the app:

```bash
python -m storyforge doctor
python -m storyforge
```

The app binds to `127.0.0.1:8000` by default and prints the exact address to open. Use the origin configured in `APP_BASE_URL`; for the `.env.example` default, open `http://127.0.0.1:8000`. `http://localhost:8000` and `http://127.0.0.1:8000` are different browser cookie origins. Every HTTP request from another origin redirects to the configured URL before session handling, so Twitch OAuth state and its cookie stay on the same origin. Callback failures return to the configured app home with a safe message instead of a JSON error page. Never expose the demo password form to the public internet.

The built-in Uvicorn runner serves plain HTTP and does not terminate TLS. If it prints repeated `Invalid HTTP request received` warnings while you try to connect, open the exact `http://...` URL printed at startup; an HTTPS/TLS request sent to this HTTP port cannot reach the app's redirect handler. The Twitch registered redirect URI must exactly equal `APP_BASE_URL/auth/callback`. The sample `.env.example` uses `http://127.0.0.1:8000`; the current local `.env` uses `http://localhost:8000`, so its callback is `http://localhost:8000/auth/callback`. A public HTTPS `APP_BASE_URL` requires a separately configured TLS reverse proxy; this development runner does not provide one.

## Configuration

The diagnostic lists every supported environment variable, local shape validation, and external verification status without printing values:

```bash
python -m storyforge doctor
```

`python -m storyforge doctor --live` makes bounded provider requests. It may refresh the encrypted host token and it may incur model usage charges. It verifies Twitch OAuth identity and one validated model response only; it does not prove EventSub chat delivery. For environment variable names and meaning, see `.env.example`.

### Twitch registration and host login

1. Register a Twitch Developer application at <https://dev.twitch.tv/console/apps>.
2. Set the registered OAuth redirect URI to the exact value `APP_BASE_URL/auth/callback`. For example, with `APP_BASE_URL=https://storyforge.example`, register `https://storyforge.example/auth/callback` exactly.
3. Configure `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, numeric `TWITCH_BROADCASTER_ID`, and `TWITCH_READER_ID`. This single-account MVP requires reader ID and broadcaster ID to match.
4. Set `STORYFORGE_MODE=live`, a unique `STORYFORGE_SECRET` of at least 32 characters, and a valid Fernet `TOKEN_ENCRYPTION_KEY`. Tokens are encrypted in SQLite; changing the Fernet key makes the old token unreadable and requires host re-authorization.
5. Use HTTPS for a public `APP_BASE_URL`. HTTP is accepted only for loopback development. Start StoryForge, choose **Sign in with Twitch as Host**, and authorize the configured broadcaster account. Twitch requests `user:read:chat` for the EventSub chat subscription.
6. Confirm `/health` reports `LIVE_TWITCH`, then verify actual messages from the configured channel. `LIVE_TWITCH` means a subscription was accepted and the WebSocket session welcomed; it does not claim recovery of messages lost during a disconnect.

Viewers may use **Connect Twitch Persona** to authenticate profile editing. Chat messages are bound to Twitch IDs received in EventSub; a display name or submitted ID cannot authorize a profile edit.

### Viewer commands and personas

In the real configured Twitch channel, viewers can use:

| Command | Effect |
|---|---|
| `!join` | Create or reconnect the Twitch-ID-bound persona |
| `!persona scholar` | Choose an allowed archetype |
| `!trait brave` | Choose an allowed trait |
| `!avatar random` | Change the procedural avatar accessory |
| `!vote A` | Cast or change a vote during an open round |
| `!line ...`, `!act ...`, `!twist ...` | Queue a bounded contribution for host review |
| `!profile`, `!story`, `!recap`, `!help` | No chat reply is sent; use the website and OBS overlay for feedback |
| `!leave` | Delete the persona and pseudonymize its historical contributions and votes |

The browser persona editor is available after Twitch login and only edits the identity authenticated by that browser session. Archetypes, traits, colors and accessories are validated; revisions are recorded. Recognized commands share a 0.75-second per-viewer cooldown; contributions have an additional 2-second cooldown. Wait briefly between commands. Unknown and informational commands do not write durable chat receipts. Cooldowns are process-local and do not coordinate multiple workers. The website and OBS overlay show results; StoryForge sends no replies to Twitch chat. In demo mode, the host simulator injects synthetic messages and is not live Twitch evidence, and demo host login is restricted to loopback requests.

### AI model setup

Set `AI_BASE_URL`, `AI_API_KEY`, and `AI_MODEL` for an HTTPS provider base URL compatible with `/chat/completions` and JSON-object response format. Enable `STORYFORGE_MODE=live` to use it. The provider and model must support the request parameters, including `response_format: {"type":"json_object"}`. The response is checked for a title, narrative, and two or three distinct choices. The UI distinguishes `FAILED`, `AWAITING APPROVAL`, `AI-GENERATED`, and `DEMO-GENERATED`; generation state survives refresh and restart. Explicit truncation, malformed output, authentication errors, and provider errors fail visibly; the app does not relabel deterministic demo text as AI.

Local settings validation does not verify a provider. Use `doctor --live` for a real, bounded inference request and confirm a saved proposal is labeled AI-GENERATED before approval.

### Host controls and OBS

The host can create a story world, generate and review a proposal, approve it into canon, start and close votes, moderate viewer contributions, add host-authored lines/actions/twists, pause/resume, finish, and fork from a prior canonical node. Host-only actions require the host session and CSRF token. SQLite is authoritative; old branches are retained.

In OBS, add a **Browser Source** pointed to `http://127.0.0.1:8000/overlay` on the same computer and set its dimensions to **1920 × 1080**. The page shows connection/demo state, story stage, current scene, viewer persona cards and vote totals. `/graph.svg` displays the branch history. A three-second full-page refresh may flicker; the overlay does not use server push.

## Known limitations

- The stored host token and broadcaster identity, active EventSub subscription, and a real schema-valid model response passed redacted live probes. Host Studio previously saved and approved an `AI-GENERATED` canonical scene. The current live chat counters show no received notifications, so real `!join`, persona edits, votes and branch transitions remain unverified. A fresh OAuth code exchange using the currently configured client secret is also unverified.
- Single-process SQLite and in-memory command cooldowns suit this MVP, not multi-worker deployment.
- Informational chat commands do not send outbound Twitch messages.
- The overlay refreshes the full document; no camera, voice, generated-image or other optional media feature is implemented.
- The app has not received an independent production security assessment. Local `.env` and SQLite database files are now restricted to owner-only POSIX permissions. Rotate credentials that may have appeared in the previously shared ZIP or earlier diagnostic output; reauthorize or migrate the encrypted token before rotating its Fernet key.
- The hackathon requires a newly created project during its submission period, a real Codex session ID, accessible source repository, a public YouTube demo under three minutes showing real Twitch and Codex, and a completed Devpost submission. See `submission/SUBMISSION_CHECKLIST.md`; no submission-ready claim is made here.
